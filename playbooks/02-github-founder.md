# Playbook 02 · 开源开发者 sourcing（潜在创业者）

## 口径
- "近 N 个月获得 1k+ Stars"按最严格的理解执行：窗口内**新建**，且已超过阈值。这样同时满足"窗口内新增"的理解。
- 年龄段：90 后 = 1990–1994，95 后 = 1995–1999，00 后 = 2000 年及以后。

## 1 发现：`scripts/github_discover.py`
- 用 GitHub 搜索接口 `created:A..B stars:>=N`，按 7 天切片，突破单次查询 1000 条的上限。

## 2 过滤：`scripts/github_screen.py`
- 规则：去掉 fork、归档；名称、描述、topics 里含 awesome、tutorial、roadmap、教程、资源、合集等词的去掉；大厂和机构官方账号去掉（见 BIG_ORGS 列表）。
- 人工复核"创新型"，排除账号池、反向代理、逆向工程、盗版客户端、网盘解析、资料镜像、NSFW 等。

## 3 定位主要开发者
- 优先用贡献者 API 计算提交占比（≥40% 视为主要开发者）。接口受限时，退回"个人仓库的所有者"，并在局限里写明。
- 华人信号（满足其一即进入候选）：中文描述；所在地为中国大陆或港澳台城市；全名是拼音姓氏。用 search/users 的 `user:a user:b location:x location:y` 批量 OR 查询，一条查询能判断 7–8 个账号。

## 4 补全与年龄核实（最难的一步）
证据优先级：
1. 本人简历、Gist、个人主页上的时间线
2. 学校公示：奖学金、推免、毕业生去向名单
3. OpenReview 档案：会自填教育经历和年份
4. 媒体人物报道
5. 社区自述：V2EX、知乎等

推算规则：本科入学年份 − 18 = 出生年份（推断）。如果推出的年份离年龄段边界不到 1 年，必须再找一条独立证据。

## 5 评估：潜在创业者信号
- 已经创业过，或主页写着 stealth、building something
- 连续做出过高星项目
- 研究方向和产品化路径清晰
- **反例**：已经是头部 KOL 或已获大额融资，属于"已被市场发现"，只作备选。

## 6 输出
- 严格遵守题目字段和字数（例如概述 50 字、profile 200 字），用脚本数字数。
- 核实信息单独成表（出生年份、证据、等级、华人依据、主要开发者依据），不占用题目字段的字数。
- 让三人串成一个判断，例如"调度层 / 反馈层 / 记忆层"。
